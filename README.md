# AFRA — Internal Financial Request & Approval System

این پروژه یک سامانه داخلی Workflow برای ثبت درخواست مالی، بررسی، پرداخت، کنترل پرداخت و تأیید نهایی هلدینگ افرا است.

## جریان واقعی درخواست

1. User 1 / کارشناس مالی: ایجاد پیش‌نویس و ارسال درخواست
2. User 2 / مدیر بازرگانی: بررسی اولیه و تأیید یا برگشت با دلیل
3. User 3 / مدیر مالی: ثبت پرداخت کامل + رسید PDF
4. User 4 / کارشناس مالی: کنترل پرداخت و تأیید یا برگشت
5. User 5 / مدیرعامل: بررسی نهایی و سپس تأیید نهایی
6. بعد از تأیید نهایی: وضعیت `COMPLETED` و تمام رویدادها در دیتابیس ثبت می‌شوند.

تمام تغییر وضعیت‌ها در Backend اعتبارسنجی می‌شوند و Frontend به‌تنهایی نمی‌تواند مرحله‌ای را رد کند.

## کاربران اولیه

- User 1 — فرزانه دانشی — کارشناس مالی — `فرزانه دانشی ۱`
- User 2 — سعید فروتن — مدیر بازرگانی — `سعید فروتن`
- User 3 — محمد اسماعیلی — مدیر مالی — `محمد اسماعیلی`
- User 4 — فرزانه دانشی — کارشناس مالی — `فرزانه دانشی ۲`
- User 5 — وحید فروتن — مدیر عامل — `وحید فروتن`

رمز اولیه همه: `123456`
شماره اولیه همه: `09397439928`

> این رمز فقط برای راه‌اندازی/تست اولیه است و قبل از استفاده واقعی باید تغییر کند.

## تکنولوژی

- Next.js App Router
- React
- Tailwind CSS
- Prisma ORM
- SQLite برای توسعه محلی
- PostgreSQL برای استقرار واقعی شرکت پیشنهاد می‌شود
- Session مبتنی بر HttpOnly cookie
- Password hashing با Node scrypt

## دیتابیس

Prisma لایه دسترسی به دیتابیس است. اطلاعات درخواست، اقلام، Approvalها، Paymentها، Taskها، Activityها، Sessionها و تنظیمات کاربران در دیتابیس ذخیره می‌شوند.

برای توسعه محلی:

```cmd
npm install
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

برای مشاهده دیتابیس:

```cmd
npm run db:studio
```

## نکته مهم برای استقرار واقعی

SQLite برای محیط چندکاربره شرکتی و اجرای همزمان درخواست‌ها گزینه نهایی نیست. قبل از Production باید دیتابیس PostgreSQL روی سرور شرکت/Cloud قرار بگیرد، `DATABASE_URL` با Secret Manager تنظیم شود و فایل‌های رسید نیز از `public/uploads` به Object Storage یا فایل‌سرور امن منتقل شوند.

همچنین قبل از Production باید HTTPS، backup روزانه، retention، لاگ سرور، محدودیت دسترسی فایل‌ها، rate limiting ورود، سیاست تغییر رمز، و تست کامل workflow روی سرور نهایی انجام شود.
